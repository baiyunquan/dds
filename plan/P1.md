# P1: Native CPU Compiler Optimization

**Enable -march=native (Clang/GCC) on Linux/macOS and /arch:AVX2 (MSVC/clang-cl) on Windows
via a new `--config=native` build profile. Zero source code changes; only .bazelrc and
CPPVARIABLES.bzl are modified.**

## Steps

### Step 1 — Add `native` config_setting to BUILD.bazel  (depends on nothing)
In root `BUILD.bazel`, after the existing `asan` config_setting, add:
```python
config_setting(
    name = "native_cpu",
    define_values = {"native": "true"},
)
```

### Step 2 — Add DDS_NATIVE_EXTRA_OPTS to CPPVARIABLES.bzl  (depends on step 1)
Append to `CPPVARIABLES.bzl`, after the existing `DDS_SCHEDULER_DEFINE` block:
```python
# Enable host-CPU-tuned code generation via --define=native=true
# Usage: bazel build --define=native=true -c opt //...
DDS_NATIVE_EXTRA_OPTS = select({
    "//:native_cpu": select({
        "//:build_windows": ["/arch:AVX2"],
        "//:debug_build_windows": ["/arch:AVX2"],
        "//conditions:default": ["-march=native"],
    }),
    "//conditions:default": [],
})
```

### Step 3 — Wire DDS_NATIVE_EXTRA_OPTS into library/src/BUILD.bazel  (depends on step 2)
In `library/src/BUILD.bazel`, load `DDS_NATIVE_EXTRA_OPTS` from `CPPVARIABLES.bzl` and
append it to `copts` in both the `dds` and `testable_dds` cc_library targets:
```python
load("//:CPPVARIABLES.bzl", "DDS_CPPOPTS", "DDS_LINKOPTS", "DDS_LOCAL_DEFINES",
     "DDS_NATIVE_EXTRA_OPTS")
# ...
cc_library(
    name = "dds",
    copts = DDS_CPPOPTS + DDS_NATIVE_EXTRA_OPTS,
    ...
)
```
Same change for `testable_dds`.

Also propagate to `library/tests/BUILD.bazel` for the `dtest` target:
```python
load("//:CPPVARIABLES.bzl", "DDS_CPPOPTS", "DDS_LINKOPTS",
     "DDS_LOCAL_DEFINES", "DDS_SCHEDULER_DEFINE", "DDS_NATIVE_EXTRA_OPTS")
# ...
cc_binary(
    name = "dtest",
    copts = DDS_CPPOPTS + DDS_NATIVE_EXTRA_OPTS,
    ...
)
```

### Step 4 — Add build:native shortcut to .bazelrc  (parallel with steps 1-3)
Append to `.bazelrc`:
```
# Host-CPU-tuned build — enables -march=native or /arch:AVX2
# Usage: bazel build --config=native -c opt //...
build:native --define=native=true
```

### Step 5 — Build and run benchmark  (depends on steps 1-4)
```
bazel build --config=native -c opt //library/tests:dtest
bazel-bin/library/tests/dtest.exe -f hands/list100.txt  -s solve -n 1
bazel-bin/library/tests/dtest.exe -f hands/list100.txt  -s solve -n 4
bazel-bin/library/tests/dtest.exe -f hands/list100.txt  -s solve -n 8
bazel-bin/library/tests/dtest.exe -f hands/list1000.txt -s solve -n 4
bazel-bin/library/tests/dtest.exe -f hands/list1000.txt -s solve -n 8
```
Record times and compare against `perf/baseline.md` from P0.

### Step 6 — Run full test suite  (depends on step 5)
```
bazel test --config=native //...
```

### Step 7 — Append results to perf/baseline.md  (depends on steps 5-6)
Add new rows:

|-------|---------|---------|----------------------|
| 100   | 4       | ?       | clang + native flags |
| 1000  | 8       | ?       | clang + native flags |

## Relevant Files

- `.bazelrc` — add `build:native` config (4 lines)
- `BUILD.bazel` (root) — add `native_cpu` config_setting
- `CPPVARIABLES.bzl` — add `DDS_NATIVE_EXTRA_OPTS` list (~15 lines)
- `library/src/BUILD.bazel` — wire `DDS_NATIVE_EXTRA_OPTS` into `copts` for `dds` and `testable_dds`
- `library/tests/BUILD.bazel` — wire `DDS_NATIVE_EXTRA_OPTS` into `dtest` copts

## Verification

1. `bazel build --config=native -c opt //library/tests:dtest` succeeds
2. `bazel test --config=native //...` → 0 failures
3. Benchmark shows measurable improvement over P0 baseline (typically 5–15%)
4. `bazel build -c opt //...` (without `--config=native`) still works unchanged

## Decisions

- Only `.bazelrc` and build files are modified; no C++ source changes
- `-march=native` with the existing LLVM 21.1.8 toolchain will auto-select
  the best available ISA (AVX2, AVX-512, etc.) for the current machine
- Intel `icpx` path is deferred to a separate optional step (requires Intel
  oneAPI Toolkit installation); it is NOT part of this phase
- `DDS_NATIVE_EXTRA_OPTS` is an additive opt-in; default builds are unaffected
